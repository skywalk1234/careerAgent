## 二、完整流程详解

### 【第1层】接收用户输入

**入口**：[Agent_controller.java](file:///d:/desktop/university/a_fuchuang_2026/fc2026/resume-parser-service/src/main/java/group/resumeparserservice/controller/Agent_controller.java)

```
用户请求
  ↓
POST /users/me/home/assistant/sessions/{sessionId}/messages
  ↓
Agent_controller.startChatting()
  ├── 生成全局唯一 messageId (IdGenerator.generateShortId)
  ├── 调用 assistantService.sendMessage() 将请求缓存到 Redis（含 sessionId, messageId, userId）
  ├── 构造 UserMessage（role="user", content, status="succeeded"）
  ├── 构造 AssistantMessage（role="user", agentTrace 初始状态）
  ├── 构造 StreamConfig（protocol="sse", url="/.../stream"）
  └── 返回 Result 给前端，指示用 SSE URL 进行流式连接
```

**关键点**：采用**两步式**通信模式——先创建消息（HTTP），再建立 SSE 流式连接获取增量回复。

**计划生成规则**（来自提示词约束）：

1. 第一步通常是 `profile_eval`（除非已有用户信息）
2. 如果需要岗位匹配 → 包含 `match_and_recommend`
3. 如果需要职业规划 → 包含 `route_planning`
4. 如果需要报告 → 包含 `report_custom`
5. 最后一步通常不调用专家，由 AI 直接生成结果

### 【第5层】计划执行（executePlanAndCollectResults）

对计划中每个步骤进行**循环执行**：

```
for each TaskStep in plan:
  │
  ├── ① 检查任务控制状态: checkTaskControl()
  │     ├── 从 Redis 获取 TaskControl 对象
  │     ├── 如果 status="paused" → 发送 task_control:paused 事件
  │     │   └── CountDownLatch.await() 阻塞等待（最多5分钟）
  │     │       └── RedisMessageSubscriber 接收 resume/cancel 消息后 latch.countDown()
  │     ├── 如果 status="cancelled" → 抛出异常终止流程
  │     └── 如果 status="running" → 继续执行
  │
  ├── ② 发送 "trace_step" 事件（标记当前活跃步骤）
  │
  ├── ③ 审批关卡（仅 match_and_recommend 专家需要）
  │     ├── 生成 approvalId
  │     ├── 发送 "approval_required" 事件给前端
  │     ├── 保存审批信息到 Redis
  │     ├── CountDownLatch.await() 阻塞等待审批（最多5分钟）
  │     ├── 等待期间用户可通过 POST /message/{messageId}/approvals 审批
  │     │   └── AssistantService.processApproval() → Redis Pub/Sub 发布消息
  │     │   └── RedisMessageSubscriber 接收 → latch.countDown()
  │     ├── 获取审批决策
  │     │   ├── "approve" → 继续执行
  │     │   ├── "reject"  → 设置 step.status="skipped"，跳过
  │     │   └── "timeout" → 跳过
  │     └── 审批通过后继续
  │
  ├── ④ 发送 "tool_call" 事件（通知前端开始调用工具）
  │
  ├── ⑤ 调用专家工具: callTool(toolName, toolParams)
  │     └── 根据 toolName 映射到 Functions_calling 的对应方法
  │
  ├── ⑥ 保存工具结果到 Redis
  │     ├── 独立存储: assistant:tool_result:{messageId}:{stepId}
  │     └── 上下文累积: assistant:context:{messageId}（Redis List，右推）
  │
  ├── ⑦ 发送 "tool_result" 事件（包含结果摘要，最长50字符）
  │
  └── ⑧ 更新步骤状态为 "completed"，保存到 Redis
```

### 【第7层】上下文管理

系统采用了**多级缓存+持久化**的上下文管理策略：

```
┌──────────────────────────────────────────────────────────────────┐
│                    Redis 缓存体系                                 │
│                                                                  │
│  assistant:request:{sessionId}:{messageId}  → ChatVO (请求体)    │
│  assistant:userId:{sessionId}:{messageId}   → userId             │
│  assistant:plan:{messageId}                 → List<TaskStep>     │
│  assistant:task:{sessionId}                 → AgentTaskVO        │
│  assistant:context:{messageId}              → Redis List (工具结果累积)│
│  assistant:tool_result:{messageId}:{stepId} → String (单步结果)   │
│  assistant:final_result:{messageId}         → String (最终结果)   │
│  assistant:approval:{approvalId}            → Map (审批信息)      │
│  assistant:actions:{messageId}              → List<Map> (推荐操作) │
│  assistant:task_control:{taskId}            → TaskControl (控制状态)│
│                                                                  │
│  所有 Key 的 TTL = 300 秒（5分钟）                                │
└──────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                    数据库持久化                                    │
│                                                                  │
│  chat_session 表 → sessionId, userId, title, lastMessagePreview  │
│  chat_message 表 → messageId, sessionId, role, content,           │
│                    actions(JSON), agentTrace(JSON), status       │
└──────────────────────────────────────────────────────────────────┘
```

**上下文流转路径**：

1. **历史消息** → 从 `chat_message` 表加载 → 传给 `AI_steps_planning` 生成计划
2. **计划步骤** → AI 生成 → 存入 Redis → 执行时读取
3. **工具执行结果** → 逐个存入 Redis List → 最后传给 `AI_comprehend` 汇总
4. **审批状态** → 存入 Redis → 通过 Redis Pub/Sub 实现跨线程通信

### 【第8层】结果汇总与最终输出（generateAndSendFinalResult）

```
generateAndSendFinalResult()
  │
  ├── ① 发送 "steps_completed" 事件
  │
  ├── ② 构建最终输出提示词: AI_agent_prompt.buildSystemPrompt(goal)
  │     ├── 要求 100-200 字回答
  │     └── 要求在回答末尾附加 ACTIONS {...} END 格式的 JSON（推荐操作）
  │
  ├── ③ 调用大模型 (qwen-max) 流式生成
  │     └── streamingChatClient.prompt(prompt).stream().content()
  │
  ├── ④ 流式处理每个 chunk
  │     ├── 检测 "ACTIONS" 标记前 → 正常流式输出 "delta" 事件
  │     ├── 检测 "ACTIONS" 标记后 → 截取并缓存 actions 内容
  │     ├── 检测 "END" 标记 → 解析 actions JSON → 保存到 Redis
  │     └── 每段增量通过 "delta" 事件 SSE 推送
  │
  ├── ⑤ 流完成后的收尾工作
  │     ├── 发送 "done" 事件（含完整 content + actions + agentTrace）
  │     ├── saveChatHistory() 持久化：
  │     │     ├── 更新 chat_session（title, lastMessagePreview）
  │     │     ├── 保存 user_message（role=user）
  │     │     └── 保存 assistant_message（role=assistant, actions, agentTrace）
  │     └── emitter.complete() 关闭连接
  │
  └── 异常处理
        └── 发送 "error" 事件 + emitter.completeWithError()
```

**值得注意的设计**：最终输出采用的是**流式非流式混合模式**——文本部分是 SSE 流式推送（逐 chunk），但工具调用部分是阻塞同步的。这意味着前端会在工具执行阶段看到步骤进度，然后在 AI 生成最终回答时看到流式输出的文本。

### 【第9层】任务控制机制

```
用户请求 → POST /users/me/home/assistant/tasks/{taskId}/control
         body: {"action": "pause" | "resume" | "cancel" | "retry"}
  ↓
Agent_controller.controlTask()
  └── assistantService.controlTask(taskId, action)
        └── TaskControlService.controlTask(taskId, action)
              ├── 创建/更新 TaskControl 对象（持久化到 Redis）
              ├── 通过 Redis Pub/Sub 发布控制消息
              │     └── channel: "task_control:{taskId}"
              └── RedisMessageSubscriber 接收后
                    ├── handleTaskControlMessage()
                    └── latch.countDown() 唤醒等待线程
```

**同步原语**：使用 `CountDownLatch` 实现**阻塞等待→Redis消息唤醒**的跨线程通信模式。主执行线程在执行步骤前检查控制状态，如果任务被暂停则阻塞，直到订阅到恢复/取消消息。

### 【第10层】审批机制（仅 match_and_recommend 专家）

```
执行到 match_and_recommend 步骤时
  │
  ├── 生成 approvalId
  ├── 发送 "approval_required" 事件给前端
  │     └── 包含 taskId, stepId, tool.name, tool.params, tool.approvalId
  │
  ├── 保存审批信息到 Redis
  │     └── assistant:approval:{approvalId} → {taskId, stepId, toolName, status="pending"}
  │
  ├── CountDownLatch.await() 阻塞等待（最多5分钟）
  │     └── latch 注册到 RedisMessageSubscriber.latchMap
  │
  │                    ╔══════════════════════════════╗
  │        ╔═══════════╣       用户审批操作           ╠═══════════╗
  │        ║           ╚══════════════════════════════╝           ║
  │        ║                                                     ║
  │        ║  POST /message/{messageId}/approvals                ║
  │        ║  body: {approvalId, decision, comment}              ║
  │        ║                                                     ║
  │        ║  AssistantService.processApproval()                 ║
  │        ║    ├── 验证 messageId 匹配                         ║
  │        ║    ├── 更新 Redis 审批状态                          ║
  │        ║    └── stringRedisTemplate.convertAndSend()         ║
  │        ║        └── channel: "approval:{approvalId}"        ║
  │        ║                                                     ║
  │        ║  RedisMessageSubscriber                              ║
  │        ║    ├── handleApprovalMessage()                      ║
  │        ║    ├── approvalResultMap.put(approvalId, decision)   ║
  │        ║    └── latch.countDown() 唤醒主线程                  ║
  │        ╚══════════════════════════════════════════════════╝
  │
  ├── 被唤醒后，从 approvalResultMap 获取决策
  │     ├── "approve" → 执行工具调用
  │     ├── "reject"  → 步骤标记 "skipped"，跳过
  │     └── "timeout" → 跳过
  │
  └── 继续后续步骤执行
```

| **生涯报告润色** | `POST /roadmapping/polish`          | AI_road_mapping.polish_road_mapping() | 润色优化报告                    |

## 四、关键设计模式总结

| 模式                      | 应用场景        | 实现方式                                                     |
| ----------------------- | ----------- | -------------------------------------------------------- |
| **计划-执行（Plan-Execute）** | Agent 核心流程  | AI 先生成计划步骤列表，然后逐步骤执行                                     |
| **SSE 流式推送**            | 前端实时通信      | SseEmitter + 多类型事件（start/trace/tool_call/delta/done）     |
| **Reactive 流式输出**       | 最终结果生成      | Spring AI Flux + CountDownLatch 同步等待流完成                  |
| **发布-订阅（Pub/Sub）**      | 任务控制 & 审批   | Redis Pub/Sub + MessageListener                          |
| **CountDownLatch 同步**   | 跨线程等待       | 主线程阻塞 → Redis 消息 → 子线程唤醒                                 |
| **RAG（检索增强生成）**         | 岗位推荐 & 路径规划 | 向量检索召回 + 大模型重排序/生成                                       |
| **微服务调用**               | 专家工具实现      | Spring Cloud Feign Client（Profile_client, Career_client） |
| **审批门（Approval Gate）**  | 敏感操作保护      | match_and_recommend 执行前等待用户审批                            |
| **多级缓存**                | 上下文管理       | Redis 缓存 + 数据库持久化 + TTL 自动过期**                           |
