## 1. 目的
验证 `career-planner-web` 前端在不同操作系统、浏览器、设备、分辨率与网络环境下的兼容性，发现影响用户体验或功能失效的问题并记录复现步骤与修复建议。

> 说明：本项目不做移动端原生应用，但应在手机浏览器上可访问与可用。

## 2. 范围
- 功能点：会话创建/切换、任务编排（Task Orchestrator）、SSE 流式输出、本地 transcript 存储/恢复、岗位筛选快捷动作、报告生成/润色等关键 UX 路径。
- 平台：桌面浏览器、笔记本、平板与手机浏览器。

## 3. 测试矩阵
- 操作系统兼容性（至少覆盖）
  - Windows 10 / 11
  - macOS Monterey / Ventura
  - Ubuntu 22.04
  - iOS  Safari 浏览器
  - Android  Chrome 浏览器
- 浏览器兼容性（至少覆盖）
  - Google Chrome 最新 + N-2 版本
  - Mozilla Firefox 最新 + N-2 版本
  - Microsoft Edge 最新
  - Apple Safari 最新（macOS / iOS）
  - 注意：IE11 不作为主要支持（提醒：若需支持，需评估 polyfill）
- 设备类型
  - 台式机（1920x1080）
  - 笔记本（1366x768）
  - 手机（360x800、375x812 等）
- 分辨率 / 屏幕尺寸
  - 320x568（小屏手机）
  - 360x800、375x812（常见手机）
  - 768x1024（iPad 竖屏）
  - 1366x768、1440x900、1920x1080（桌面）
- 网络条件
  - 良好网络（100 Mbps）
  - 中等网络（5-10 Mbps）
  - 低速/受限网络（256-512 kbps）
  - 高延迟（模拟 200-500 ms 延迟）
  - 不稳定网络（断连/恢复场景）

## 4. 测试方法与工具
- 使用真实设备与浏览器优先；可用浏览器的开发者工具（Device Mode/Network Throttling）模拟移动与网络情况。
- 使用 Lighthouse（Chrome DevTools）、BrowserStack / Saucelabs（如可用）进行跨浏览器快速验证。
- 对于 SSE/流式输出，观察 Network -> EventStream（或使用抓包工具）并记录事件序列（delta/task_update/done）。
- 本地 transcript 验证：在浏览器 Console 查看 localStorage 的键：
  - `home_task_orchestrator_session_id`
  - `home_task_orchestrator_transcript`

  记录创建、清理、恢复时机与内容变化。

## 5. 测试流程（通用）
1. 部署/本地运行前端（确保后端 mock server 可用）。
2. 打开目标浏览器并清除缓存、localStorage（以保证测试一致性）。
3. 进入首页，检查首页欢迎/快捷提示是否正常。
4. 创建会话（“新对话”），在会话中执行以下关键流程：
   - 发起任务编排（3连顺序执行示例）并确认流式输出（SSE）行为；
   - 在任务完成后发起报告润色/选择任务并完成；
   - 新建第二个任务会话，完成后回到第一个会话，验证消息是否仍然存在（重点复现场景）。
5. 在不同网络条件与不同浏览器上重复步骤，记录差异。

## 6. 常用检查点
- UI：布局错位、溢出、遮挡、字体与图标缺失。
- 功能：会话消息加载/切换是否正确、SSE 流是否断连、进度条是否流式更新（0→100%）、快捷动作（apply_recommended_job/refine_match_recommendations）是否触发。
- 本地存储：`home_task_orchestrator_transcript` 的内容是否在创建/发起任务/恢复时符合预期。
- 控制台错误：关注 JS 错误、跨域、EventSource 错误、localStorage quota 错误。

## 12. 附加测试用例与兼容性场景（扩展）
下面列出覆盖项目核心功能与常见兼容性风险的详细测试用例示例，便于在不同平台与浏览器上复现和定位问题。

### TC-CORE-01 会话创建与切换恢复（桌面浏览器）
- 测试目标：验证在桌面浏览器（Chrome/Firefox/Edge）中创建多个会话并来回切换时，消息不会丢失。
- 前置条件：清空 localStorage；使用 Chrome/Firefox/Edge 最新版本。
- 步骤：
  1. 打开首页，创建会话 A；在 A 中发一条用户消息并等待助手回复完成。
  2. 新建会话 B，在 B 中发起一个短对话并完成。
  3. 切回会话 A，检查 A 的消息历史是否完整。
- 预期：会话 A 的所有历史消息保留；UI 显示与后端返回一致。

### TC-SSE-01 流式输出稳定性与重连（网络抖动）
- 测试目标：验证 SSE 在网络中断/恢复、延迟大的情况下是否能正确重连或前端能回退到本地 transcript 恢复。
- 前置条件：Chrome DevTools Network Throttling 用于模拟高延迟/断连。
- 步骤：
  1. 发起一个需长时间流式输出的任务（Task Orchestrator）。
  2. 在输出进行中模拟网络断连（Offline），等待若干秒后恢复网络。
  3. 观察前端是否能在恢复后继续接收 `task_update` / `delta` / `done` 事件或显示从本地 transcript 恢复的信息。
- 预期：前端应尝试重连或在断网期间不丢失已接收片段；恢复后最终显示 `succeeded` 并包含 taskResultCard。

### TC-PROGRESS-01 进度条增量更新
- 测试目标：确保任务进度以流式方式增量更新
- 步骤：
  1. 发起 Task Orchestrator 的 3 步任务，观察 `task_update` 事件。
  2. 验证进度计数器随 `agentTrace.steps` 的 progress 变化更新（至少出现数次增量变化）。
- 预期：进度以多次小步长更新直至 100%，UI 中进度条平滑而非瞬变。

### TC-TRANSCRIPT-01 本地 transcript 写入/恢复/多标签一致性
- 测试目标：验证 `home_task_orchestrator_transcript` 的写入、清理、恢复逻辑，以及在多标签并发下的数据一致性。
- 前置条件：使用 Chrome，打开两个标签页登录同一用户。
- 步骤：
  1. 在标签页 A 发起任务并等待部分输出，确认 localStorage 写入存在对应 sessionId。
  2. 在标签页 B 发起另一个任务，观察是否会覆盖或清空 transcript（记录 set/clear 操作时机）。
  3. 回到标签页 A，尝试恢复并检查是否缺失历史。
- 预期：transcript 不应被错误覆盖；若发生覆盖需记录调用栈并修复 `clearTaskTranscript` 的调用条件。

### TC-ACTION-01 快捷动作行为（`apply_recommended_job`）
- 测试目标：验证当助手返回 `apply_recommended_job` action 且当前路由为 `/jobs` 时，前端能正确触发筛选与可选的自动选中。
- 步骤：
  1. 在 `/jobs` 页面触发“帮我推荐一个岗位”快捷消息（或模拟助手返回 action）。
  2. 验证前端是否调用筛选函数、页面展示岗位列表、并根据 `autoSelect` 自动高亮一项（若存在）。
- 预期：action 被识别并触发对应路由/筛选逻辑；无 JS 错误。

### TC-REFINE-01 触发重匹配（`refine_match_recommendations`）与轮询
- 测试目标：验证 refine 流程会触发后端重匹配并在 `processing->succeeded` 状态切换后展现新结果。
- 步骤：
  1. 通过助手 action 触发 `refine_match_recommendations`，观察前端是否发起 refine 请求并开始轮询。
  2. 等待或模拟后端完成，确认前端在 `succeeded` 后展示新推荐并解除 loading 状态。
- 预期：轮询间隔合理（参照 `getPollAfterMs`），最终收到并渲染新结果。

### TC-REPORT-01 报告润色与一键触发（`one_click_polish`）
- 测试目标：验证报告润色的批准流程、自动填参与任务创建流程。
- 步骤：
  1. 在助手消息返回包含 `one_click_polish` action 时，点击触发确认弹窗并选择确认。
  2. 验证前端是否把 `polishPayload` 正确传递到 `createHomeAgentTask` 或相应接口，并在任务完成后显示润色结果或下载链接。
- 预期：审批弹窗逻辑正常；任务创建与后续展示无异常。

### TC-UPLOAD-01 简历上传与解析兼容性
- 测试目标：验证文件上传（PDF/Docx/图片）在不同浏览器上的兼容性与解析触发。
- 步骤：
  1. 在简历上传入口选择不同格式与大小（边界：接近 10MB 上限），在 Chrome / Firefox / Safari 上分别尝试上传并解析。
  2. 检查后端返回解析结果与前端展示是否一致；观察超大文件与错误格式的提示。
- 预期：支持 `pdf/jpg/jpeg/png/docx/doc`；超限时给出友好错误提示并不崩溃页面。

### TC-RESP-01 响应式布局与分辨率适配
- 测试目标：验证关键页面（聊天窗口、任务编排面板、岗位筛选面板）在不同分辨率下布局合理且没有遮挡。
- 步骤：
  1. 使用 Developer Tools 的 Device Mode 或真实设备测试：320x568、375x812、768x1024、1366x768、1920x1080。
  2. 重点检查侧边栏折叠、对话滚动、任务面板弹窗位置、关键按钮是否可点击。
- 预期：桌面端布局保留主要交互；移动端通过浏览器可访问且功能可用（UI 可能为简化布局）。

### TC-NET-01 网络条件与超时策略
- 测试目标：验证在慢速网络与高延迟下的用户反馈（loading、超时提示、重试机制）。
- 步骤：
  1. 使用 Network Throttling 模拟 256 kbps、500 ms 延迟；发起复杂任务与文件下载。
  2. 观察前端是否给出超时/重试提示；SSE 是否因超时被断开且是否能恢复或提示用户重试。
- 预期：用户得到合理提示而非无响应；关键操作可重试。

### TC-SAFARI-01 iOS Safari 特殊行为（后台节流与 EventSource）
- 测试目标：验证 iOS Safari 在后台或屏幕锁定时对 SSE 的影响，并记录任何事件丢失或延迟表现。
- 步骤：
  1. 在 iPhone 上用 Safari 发起任务，随后切换到主屏或锁屏一段时间，再回来查看结果。
  2. 对比 EventStream 的时间戳与前端展示，查看是否有丢失或延迟。
- 预期：iOS 可能在后台节流导致 SSE 暂停，前端需在返回前台时做补偿或从本地 transcript 恢复展示。

### TC-INC-01 隐身模式 / localStorage 受限场景
- 测试目标：验证在浏览器隐身/限制 localStorage 情况下，应用不会崩溃并能给出清晰提示。
- 步骤：
  1. 在隐身窗口打开应用，发起任务与会话切换；查看是否出现 localStorage quota 错误或异常。
  2. 若 localStorage 不可用，验证前端是否退回到只使用内存状态并提示用户局部功能受限。
- 预期：不致命崩溃；功能退化并给出提示。

### TC-CONC-01 多标签并发发起任务（sessionId 冲突）
- 测试目标：验证多个标签页同时发起任务导致的 sessionId 覆盖或 transcript 丢失问题能被检测并妥善处理。
- 步骤：
  1. 在标签页 A、B 同时点击“发起任务/新建会话”，观察 `home_task_orchestrator_session_id` 的变化与 `home_task_orchestrator_transcript` 内容。
  2. 记录是否发生 `clearTaskTranscript` 调用覆盖其它会话的情况。
- 预期：避免误清空非活跃 session 的 transcript；如发生覆盖，需调整清理策略（仅清理已确定为“旧的任务会话”）。

## 14. 示例测试结果（示意，非真实执行）
下面为每个关键用例给出示意性的“实际测试结果”，用于 QA 参考与缺陷优先级评估。注意：以下结果为模拟示例，并非现场执行所得，仅作为填报模板与参考。

### TC-CORE-01 会话创建与切换恢复（桌面浏览器）
- 执行环境（示意）：Windows 11 + Chrome 114
- 实际结果（示意）：创建会话 A/B 并切换，A 的历史消息在多数切换中保留；少数场景（快速并发创建会话）出现 UI 刷新短暂空白，刷新后恢复。
- 结论：功能总体可用，建议在前端增加切会话时的保护性合并逻辑与加载占位 UI（P1）。

### TC-SSE-01 流式输出稳定性与重连（网络抖动）
- 执行环境（示意）：macOS + Chrome，网络模拟：断连 5s
- 实际结果（示意）：SSE 在短期断连后能重连并接收后续事件；已接收片段保留，但个别 delta 片段在断网期间丢失，最终 done 事件到达并附带完整 taskResultCard。
- 结论：重连逻辑可接受，但需在断网/恢复时用本地 transcript 做补偿与可视化提示（P1）。

### TC-PROGRESS-01 进度条增量更新（0→100%）
- 执行环境（示意）：Ubuntu + Firefox
- 实际结果（示意）：进度条出现多次增量更新；在极短步骤场景中偶见瞬变（跳帧），但总体显示从 0 到 100%。
- 结论：通过，建议平滑过渡动画以提高感知（P2）。

### TC-TRANSCRIPT-01 本地 transcript 写入/恢复/多标签一致性
- 执行环境（示意）：Chrome 多标签并发
- 实际结果（示意）：复现出多标签并发下 transcript 被覆盖的风险——在标签 B 创建新任务时，localStorage 中的 `home_task_orchestrator_transcript` 被替换，回到标签 A 时历史缺失（需要手动刷新或无法恢复）。
- 结论：严重（P0/P1），已确认需加固 `clearTaskTranscript` 使用条件与多标签冲突检测；建议实现基于 sessionId 的原子合并或对冲突发出警告并避免覆盖。

### TC-ACTION-01 快捷动作行为（`apply_recommended_job`）
- 执行环境（示意）：/jobs 页面，Chrome
- 实际结果（示意）：助手返回 `apply_recommended_job` 时，前端能识别 action 并触发筛选；`autoSelect` 生效且高亮推荐项；少数 edge-case 中未找到推荐 jobId 时仅打开筛选面板。
- 结论：通过（P2），建议补充对无推荐 ID 的降级行为（提示或默认筛选）。

### TC-REFINE-01 触发重匹配（`refine_match_recommendations`）与轮询
- 执行环境（示意）：Chrome + 后端模拟较短延迟
- 实际结果（示意）：前端发起 refine 请求并开始轮询；后端完成后返回 `succeeded`，前端更新推荐列表并结束轮询；轮询间隔和超时行为符合预期。
- 结论：通过（P2）。

### TC-REPORT-01 报告润色与一键触发（`one_click_polish`）
- 执行环境（示意）：macOS + Safari
- 实际结果（示意）：触发一键润色后出现确认弹窗，确认后任务创建成功并返回 polish 结果；部分 Safari 版本在展示富文本时样式轻微错位。
- 结论：功能可用（P2），建议对富文本样式在 Safari 上做微调（P3）。

### TC-UPLOAD-01 简历上传与解析兼容性
- 执行环境（示意）：Chrome / Firefox / Safari；文件：PDF、DOCX、PNG
- 实际结果（示意）：PDF/PNG 上传与解析正常；DOCX 在部分老旧 Safari 下上传预览失败（后端仍接收并解析成功），前端需展示上传成功提示以避免用户误以为失败。
- 结论：总体通过（P2），Safari DOCX 体验需优化（P3）。

### TC-RESP-01 响应式布局与分辨率适配
- 执行环境（示意）：多分辨率模拟
- 实际结果（示意）：桌面与常见笔记本分辨率表现良好；在窄屏（320px）手机模拟下，部分侧边栏内容存在溢出或不可见按钮，需滚动才能操作。
- 结论：通过但需提升小屏可用性（P2）。

### TC-NET-01 网络条件与超时策略
- 执行环境（示意）：网络节流 256 kbps，延迟 300 ms
- 实际结果（示意）：在低速/高延迟下，SSE 连接更易超时，部分请求延迟显著，前端显示超时提示或保持 loading 状态较长。
- 结论：需在关键交互处提供更明确的超时/重试策略与用户提示（P1）。

### TC-SAFARI-01 iOS Safari 特殊行为（后台节流与 EventSource）
- 执行环境（示意）：iPhone (iOS 14/16) Safari
- 实际结果（示意）：当切到后台或锁屏后，SSE 被系统节流/暂停，部分 delta 未及时到达；返回前台后本地 transcript 可用于补全显示，但体验存在空窗期。
- 结论：iOS 行为属平台限制，需在前端增加前后台状态检测与恢复策略（P1）；建议在文档中告知用户锁屏/后台期间可能暂停流式更新。

### TC-INC-01 隐身模式 / localStorage 受限场景
- 执行环境（示意）：Chrome 隐身窗口
- 实际结果（示意）：localStorage 不可用或受限时，transcript 无法持久化，但应用不崩溃；会话在内存中可以正常进行但刷新后历史丢失。
- 结论：接受的降级策略，但应给出用户友好提示（P2）。

### TC-CONC-01 多标签并发发起任务（sessionId 冲突）
- 执行环境（示意）：Chrome 多标签
- 实际结果（示意）：证实存在 sessionId 覆盖或 transcript 被后续创建动作清理的风险（与 TC-TRANSCRIPT-01 一致），需修复。
- 结论：高优先级修复项（P0/P1），避免自动清理覆盖非当前会话的本地数据。

| Mozilla Firefox | 90+ | 支持现代 JS 特性与 Fetch；老版本存在一些 CSS/渲染差异。 |
| Apple Safari（macOS） | 13.1+ | Safari 在较旧版本对 ES modules、flex/grid 存在兼容性差异；建议尽量要求 14+。 |
| iOS Safari（Mobile） | 13.4+ | iOS 使用 WebKit，需注意后台节流与 EventSource 行为（可能在锁屏/后台暂停）。 |
| Android Chrome（手机） | 92+ | Android 上的 Chrome 与桌面兼容性接近；WebView/旧厂商浏览器除外。 |
| Opera（Chromium） | 78+ | 基于 Chromium，兼容性与 Chrome 相近。 |
| Internet Explorer（IE11） | 不支持（若需支持需额外降级与 polyfill） | Vue 3 与 Element Plus 不支持 IE11；若必须支持 IE11，需要回退到 Vue 2 并引入大量 polyfill 与构建调整，不建议。 |

注意事项：
- 如果要求支持 IE11 或非常老的浏览器，需要将构建目标降为 ES5，并加入 polyfill（core-js、regenerator 等），但这会增加维护成本与潜在 bug，且 Element Plus 无 IE 支持。
- WebGL（three.js）依赖 GPU 与浏览器对 WebGL 的支持，部分老旧集成显卡或虚拟机环境可能无法加载 3D 内容，应在低配设备上降级展示或隐藏 3D 视图。

推荐用于跨浏览器/跨设备测试的在线服务与工具：

- BrowserStack（https://www.browserstack.com）— 提供真实设备与浏览器的交互式测试及自动化（Selenium / Playwright）。
- Sauce Labs（https://saucelabs.com）— 云端跨浏览器、跨设备自动化与交互式测试平台。
- LambdaTest（https://www.lambdatest.com）— 支持实机/仿真浏览器测试、响应式预览与自动化集成。
- CrossBrowserTesting（https://crossbrowsertesting.com）— 云端实时与自动化测试服务。
- Playwright（https://playwright.dev）— 本地/CI 端到端跨浏览器自动化（支持 Chromium、Firefox、WebKit），适合做回归与兼容性脚本。
- Puppeteer（https://pptr.dev）— Headless/可视化 Chrome 自动化，适合单浏览器自动化场景。
- caniuse.com（https://caniuse.com）— 用于检查具体 Web API / CSS 特性的浏览器支持矩阵。
- Responsinator / Chrome DevTools Device Mode / Firefox Responsive Design Mode — 快速查看不同分辨率/设备下的布局。
- LT Browser（LambdaTest 提供的桌面应用）— 本地响应式预览多设备尺寸。
- BrowserShots / Screenshot-as-a-Service — 快速做静态截图兼容性对比（无交互）。

实用建议：
- 本地优先用 Playwright 做自动化回归（支持三大内核：Chromium、Firefox、WebKit），可以在 CI 中并行运行不同浏览器的测试用例。Playwright 在本地即可覆盖绝大多数兼容性断言（DOM、样式、功能）。
- 在需要验证真实手机/平板的系统行为（如 iOS Safari 的后台节流、EventSource 行为）时，优先使用 BrowserStack/LambdaTest 的真实设备或真机远程调试。
- 使用 `caniuse.com` 对具体 API（EventSource、WebGL、ES Modules 等）做逐特性支持评估，作为是否需要 polyfill 的依据。
