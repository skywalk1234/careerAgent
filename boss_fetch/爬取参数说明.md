# boss_fetch 爬取参数说明

> 爬一轮 = **1 个关键词 × 1 个城市**，每个组合拼出一个 BOSS 搜索页 URL，再滚动抓取。
> 字段值以 boss_fetch 内代码/配置为准：
> 配置样例 [crawler/config/keywords.json](crawler/config/keywords.json)，代码 [crawler/boss.py](crawler/boss.py)。

---

## ① 一级筛选：采集必填（关键词 × 城市）

| 参数 | 必填 | 含义 | 取值 / 默认 | 配置位置 |
| --- | :-: | --- | --- | --- |
| `keywords`（岗位名称/搜索词） | ✅ | 每个词 × 每个城市各搜一轮。**标题需包含该词才会保留**，词越像“完整岗位名”越准 | list，默认见 boss.py `DEFAULT_KEYWORDS`（AI应用开发工程师 / Agent应用开发工程师…） | `keywords.json` → `keywords` |
| `cities`（意向城市） | ✅ | `{城市名: 城市码}`，`--city 北京` 只取其中指定城市 | 内置 20 城码表（北京101010100、上海101020100、广州101280100、深圳101280600…） | `keywords.json` → `cities` 或 CLI `--city` |

> 城市码与职位/行业码的动态全量清单，BossFlow 参考实现见其 `backend/services/search_filter_service.py`。

---

## ② 二级筛选：BOSS 站内筛选（URL 参数，可选）

只能放 `search_filters={...}` 传（**CLI 不支持**），值只认**数字 code**（非数字或 `'0'` 会被忽略）：

| 参数 | 含义 | code 码表（常用） | 对应 URL key |
| --- | --- | --- | --- |
| `salary` | 薪资档 | `403`=3-5K, `404`=5-10K, `405`=10-20K, **`406`=20-50K**, `407`=50K+ | `salary` |
| `experience` | 经验 | `103`=1年以内, `104`=1-3年, **`105`=3-5年**, `106`=5-10年, `107`=10年+ | `experience` |
| `degree` | 学历 | **`203`=本科**, `204`=硕士, `205`=博士 | `degree` |
| `jobType` | 求职类型 | **`1901`=全职**, `1903`=兼职 | `jobType` |
| `scale` | 公司规模 | `301`=0-20人 … `306`=10000人+ | `scale` |
| `stage` | 融资阶段 | `801`=未融资 … `807`=已上市 | `stage` |
| `position` | 职位大类 | 动态清单（来自 BOSS `position.json`） | `position` |
| `industry` | 行业 | 动态清单（来自 BOSS `industry.json`） | `industry` |

> 旧参数 `salary_code`/`salary_label` 仍可用，效果等同 `search_filters["salary"]`，新代码建议统一用 `search_filters`。

## ③ 采集数量 / 停止条件

| 参数 | 必填 | 含义 | 默认 |
| --- | :-: | --- | --- |
| `new_job_target` | 否 | 每个 词×城 组合的“新岗位目标数”，达到即停 | 20 |
| `max_jobs` | 否 | 每组合最多浏览条数（上限） | 100 |
| 连续空滚次数 | 否 | 滚动 `5` 次无新岗位即认为到底，停止 | 5（写死） |
| `scroll_max_scrolls` | 否 | 滚动安全上限，自动取 `max(该值, max_jobs/10+10)` | 60 |

对应 CLI：`--new-target N --max-jobs N`；配置里可放 `keywords.json → scrape_limits`。

## ④ Chrome / 登录 / 运行参数

| 参数 | 必填 | 含义 | 默认 |
| --- | :-: | --- | --- |
| `profile_dir` | ✅(首跑) | 登录过 BOSS 的 Chrome 用户目录，Cookie 持久化；**首次需真实浏览器手动登录一次** | `./.chrome_profile` |
| `headless` | 否 | 登录完成后切无头后台跑 | `False` |
| `chrome_port` | 否 | Chrome 调试端口 | `9222`（可用环境变量 `AI_PM_CHROME_PORT` 覆盖） |
| `config_file` | 否 | keywords.json 路径 | `crawler/config/keywords.json` |
| `partial_file` | 否 | 中断续爬文件（Ctrl+C 落盘，可 `--process-partial` 续采） | `./crawl_partial.json` |

## ⑤ 入库前的清洗/过滤规则（规则可全配在 keywords.json，或调用 `process_batch` 时直接传参）

| 参数 | 必填 | 含义 | 说明 |
| --- | :-: | --- | --- |
| `relevance_keywords` | 否 | **强筛**：标题命中才保留 | 采集(`is_relevant_job`)与入库(`admission_decision`)两阶段都生效 |
| `target_keywords` | 否 | 没配上面那项时的**回退筛选词** | 默认取 `config.keywords`；**标题必须包含其一才保留** |
| `blacklist_keywords` | 否 | 标题命中即丢弃（如 销售/外包驻场） | 优先级最高 |
| `cat_rules` | 否 | 给岗位打分类标签 `cats`（如 `大模型/LLM`、`AI Agent/智能体`…） | 不配则打“通用” |
| `min_salary` | 否 | 月均薪资下限 | ⚠️ **当前仅保留参数、不实际过滤**（`avg`=月均K已算好，需要过滤请自行加判断） |

---

## 最小必填清单（开跑前至少想清楚）

| 项 | 现在要准备的 | 放哪 |
| --- | --- | --- |
| 岗位名称关键词 | 如 `大模型工程师`、`LLM应用工程师` | `keywords` |
| 意向城市 | 如 `{"北京":"101010100","上海":"101020100"}` | `cities` |
| 登录过的 Chrome | 首次 `run.py --login` 手动登一次 | `--profile`（默认 `.chrome_profile`） |
| （可选）薪资/经验/学历 | 如 `{"salary":"406","experience":"105","degree":"203","jobType":"1901"}` | `run(search_filters=…)` 代码里传 |

**实操提醒**：入库过滤是**整词子串命中**——词写太宽（如“AI”）会把销售/客服全放进来，写太窄（如“大模型算法”）又可能漏掉“LLM应用开发”这类叫法。建议按目标岗位习惯叫法列一组**完整岗位名**，再用 `blacklist_keywords` 补漏。
