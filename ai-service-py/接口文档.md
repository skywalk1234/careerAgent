# AI 求职助手服务 · 接口文档

基于 **DeepSeek** 的求职助手聊天服务（FastAPI），端口 **8086**，不经过 Java 网关，前端直连。

## 快速开始

| 入口 | 地址 |
|---|---|
| 交互式测试页面（Swagger UI） | http://localhost:8086/docs |
| 接口文档（ReDoc） | http://localhost:8086/redoc |
| 健康检查 | http://localhost:8086/health |

启动命令（在 `ai-service-py` 目录下）：

```powershell
.\venv\Scripts\python.exe main.py
```

## 通用约定

- **Base URL**：`http://localhost:8086`
- **数据格式**：JSON（`Content-Type: application/json`）
- **鉴权**：无（请求直连 AI 服务，不经过网关，无需 JWT）
- **统一前缀**：所有聊天接口都在 `/users/me/home/assistant` 下
- **时间格式**：ISO 8601 字符串（UTC）

## 2. 创建会话

### `POST /users/me/home/assistant/sessions`

创建一条新的对话会话。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `user_id` | string | 否 | 用户 ID，默认 `"111"` |
| `title` | string | 否 | 会话标题，默认 `"新对话"` |

```json
{
  "user_id": "111",
  "title": "帮我规划职业路径"
}
```

**响应 `200`：**

```json
{
  "session_id": "3f2a1b9c4d8e4f7a9b1c2d3e4f5a6b7c",
  "title": "帮我规划职业路径",
  "last_message_preview": "",
  "pinned": false,
  "favorited": false,
  "updated_at": "2026-07-31T08:00:00"
}
```

## 5. 发送消息

### `POST /users/me/home/assistant/sessions/{session_id}/messages`

把用户消息存入数据库，并返回 **SSE 流地址**，前端随后连接该地址接收 AI 增量回复（两步式设计，避免长等待阻塞）。

**路径参数：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | string | 会话 ID |

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `content` | string | 是 | 用户输入的消息内容（至少 1 个字符） |

```json
{
  "content": "帮我分析前端转 AI 岗位的可行性"
}
```

**响应 `200`：**

```json
{
  "session_id": "3f2a1b9c4d8e4f7a9b1c2d3e4f5a6b7c",
  "user_message": {
    "message_id": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6",
    "role": "user",
    "content": "帮我分析前端转 AI 岗位的可行性",
    "status": "succeeded",
    "created_at": "2026-07-31T08:00:00"
  },
  "stream": {
    "protocol": "sse",
    "url": "/users/me/home/assistant/sessions/3f2a1b9c4d8e4f7a9b1c2d3e4f5a6b7c/messages/a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6/stream"
  }
}
```

## 6. 流式接收 AI 回复（SSE）

### `GET /users/me/home/assistant/sessions/{session_id}/messages/{message_id}/stream`

以 **Server-Sent Events（SSE）** 协议逐字推送 AI 生成内容，前端通过 `EventSource` 或 fetch 流式读取。回复生成完毕后自动保存助手消息到数据库。

**路径参数：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | string | 会话 ID |
| `message_id` | string | 第 5 步返回的 `user_message.message_id` |

**注意：** 未配置 `DEEPSEEK_API_KEY` 时返回 `500`，需在 `.env` 中填写。

### SSE 事件协议

每条 SSE 消息格式：`event: <事件名>\ndata: <JSON>\n\n`

| 事件名 | 触发时机 | data 结构 |
|---|---|---|
| `start` | 开始生成 | `{"type":"start","messageId":"..."}` |
| `delta` | 每生成一段文字 | `{"type":"delta","delta":"增量文本","content":"累计完整文本"}` |
| `done` | 生成完成 | `{"type":"done","message":{...助手消息完整对象...}}` |
| `error` | 处理出错 | `{"type":"error","messageId":"...","error":"错误信息"}` |

**完整事件流示例：**

```
event: start
data: {"type":"start","messageId":"a1b2c3d4..."}

event: delta
data: {"type":"delta","delta":"前端","content":"前端"}

event: delta
data: {"type":"delta","delta":"转AI","content":"前端转AI"}

event: done
data: {"type":"done","message":{"messageId":"a1b2c3d4...","role":"assistant","content":"前端转AI…","status":"succeeded","actions":[],"agentTrace":{"status":"succeeded","activeStepId":null}}}
```

**前端消费伪代码：**

```js
const es = new EventSource(url)
es.addEventListener('delta', (e) => {
  const data = JSON.parse(e.data)
  console.log(data.delta)   // 增量文本
})
es.addEventListener('done', (e) => {
  es.close()                // 完成后关闭连接
})
es.addEventListener('error', (e) => {
  console.error(e)
})
```

## 附：完整调用时序（一次对话）

```
1. POST /sessions                     → 创建会话，拿到 session_id
2. POST /sessions/{id}/messages       → 存用户消息，拿到 message_id + stream.url
3. GET  stream.url (SSE)              → 收 start/delta/done，AI 回复逐字展示
4. GET  /sessions/{id}/messages       → 下次打开会话时展示历史
```

## 常见错误

| 状态码 | 场景 |
|---|---|
| `404` | 会话或消息不存在（`detail` 中带原因） |
| `500` | 未配置 `DEEPSEEK_API_KEY` 或 AI 调用出错 |
