# AI 求职助手服务 · 接口文档

基于 **DeepSeek** 的求职助手聊天服务（FastAPI），端口 **8086**，不经过 Java 网关，前端直连。

## 快速开始

| 入口 | 地址 |
|---|---|
| 交互式测试页面（Swagger UI） | http://localhost:8086/docs |
| 接口文档（ReDoc） | http://localhost:8086/redoc |
| 健康检查 | http://localhost:8086/health |

启动命令（在 `ai-service-py` 目录下）：

```powershell
.\venv\Scripts\python.exe main.py
```

> 注意：Windows 下已关闭 uvicorn 的 reload 模式，改代码后需手动重启。

## 通用约定

- **Base URL**：`http://localhost:8086`
- **数据格式**：JSON（`Content-Type: application/json`）
- **鉴权**：无（请求直连 AI 服务，不经过网关，无需 JWT）
- **统一前缀**：聊天接口都在 `/users/me/home/assistant` 下；岗位推荐接口在 `/jobs/recommend*` 下
- **字段风格**：响应字段使用**驼峰**（`sessionId` / `messageId` / `createdAt`），与前端约定一致
- **时间格式**：ISO 8601 字符串（UTC）
- **默认用户**：直连阶段不传用户标识，服务统一使用默认用户 `"111"`

### 统一响应外壳

聊天接口（除 SSE 流和 `/health`）都包一层响应壳，与前端 `services/http.ts` 约定一致。**岗位推荐接口（`/jobs/recommend*`）例外**：返回 `text/plain` 裸 JSON 文本、不套响应壳（见第 7、8 节），调用方直接解析 JSON 内容：

```json
{
  "code": 200,
  "msg": "success",
  "data": { }
}
```

**错误响应**同样使用该结构（HTTP 状态码与 `code` 一致）：

```json
{
  "code": 404,
  "msg": "会话不存在",
  "data": null
}
```

| HTTP 状态码 | code | 场景 |
|---|---|---|
| 200 | 200 | 成功 |
| 404 | 404 | 会话或消息不存在 |
| 422 | 422 | 请求参数校验失败 |
| 500 | 500 | 未配置 `DEEPSEEK_API_KEY` 或 AI 调用出错 |

## 2. 创建会话

### `POST /users/me/home/assistant/sessions`

创建一条新的对话会话（标题默认 `"新对话"`）。

**请求体（对齐前端 `createHomeSession`）：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scene` | string | 否 | 场景标识，默认 `"home"` |
| `temperature` | number | 否 | 采样温度，默认 `0.3` |

```json
{
  "scene": "home",
  "temperature": 0.3
}
```

**响应 `200`：**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "sessionId": "0556f155b12047758ac48f3a2d6e8819",
    "createdAt": "2026-08-02T11:31:58.983442",
    "welcomeMessage": null
  }
}
```

## 5. 发送消息

### `POST /users/me/home/assistant/sessions/{sessionId}/messages`

把用户消息存入数据库，并返回 **SSE 流地址**，前端随后连接该地址接收 AI 增量回复（两步式设计，避免长等待阻塞）。

**路径参数：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `sessionId` | string | 会话 ID |

**请求体（对齐前端 `createHomeSessionMessage`）：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `content` | string | 是 | 用户输入的消息内容（至少 1 个字符） |
| `temperature` | number | 否 | 采样温度，默认 `0.4` |
| `traceId` | string | 否 | 链路追踪 ID |
| `fileContext` | object | 否 | `{hasResumeFile, fileNames}` |
| `pageContext` | object | 否 | 页面上下文 |
| `executionMode` | string | 否 | `"auto"` / `"chat"` / `"task"` |
| `goal` | string | 否 | 任务目标 |
| `taskPolicy` | object | 否 | `{allowToolCall, maxSteps, timeoutMs}` |
| `toolContext` | object | 否 | 工具上下文 |

```json
{
  "content": "帮我分析前端转 AI 岗位的可行性",
  "temperature": 0.4,
  "traceId": "trace_home_1722...",
  "fileContext": { "hasResumeFile": false, "fileNames": [] },
  "pageContext": null,
  "executionMode": "auto",
  "goal": "",
  "taskPolicy": { "allowToolCall": true, "maxSteps": 8, "timeoutMs": 120000 },
  "toolContext": null
}
```

> 说明：当前版本只使用 `content`，其余字段仅做兼容接收（后续接入 Agent 任务时启用）。

**响应 `200`（对齐前端 `createHomeSessionMessage`）：**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "sessionId": "0556f155b12047758ac48f3a2d6e8819",
    "userMessage": {
      "messageId": "448d7e72221b45f9baf4fb34ca38cb6b",
      "role": "user",
      "content": "帮我分析前端转 AI 岗位的可行性",
      "status": "succeeded",
      "createdAt": "2026-08-02T11:31:59.111408",
      "fileNames": [],
      "agentTrace": {},
      "actions": [],
      "taskResultCard": null
    },
    "assistantMessage": {
      "messageId": "e88c8abedcac4f93adff2349bc366484",
      "role": "assistant",
      "content": "",
      "status": "processing",
      "createdAt": "2026-08-02T11:31:59.117395",
      "fileNames": [],
      "agentTrace": null,
      "actions": [],
      "taskResultCard": null
    },
    "stream": {
      "protocol": "sse",
      "url": "/users/me/home/assistant/sessions/0556f155b12047758ac48f3a2d6e8819/messages/448d7e72221b45f9baf4fb34ca38cb6b/stream"
    }
  }
}
```

> `assistantMessage` 是占位对象（内容为空、状态 `processing`），前端拿它的 `messageId` 去连接 SSE 流，真实内容由流式事件推送。

## 6. 流式接收 AI 回复（SSE）

### `GET /users/me/home/assistant/sessions/{sessionId}/messages/{messageId}/stream`

以 **Server-Sent Events（SSE）** 协议逐字推送 AI 生成内容，前端通过 `EventSource` 或 fetch 流式读取。回复生成完毕后自动保存助手消息到数据库。

**路径参数：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `sessionId` | string | 会话 ID |
| `messageId` | string | 第 5 步返回的 `userMessage.messageId` |

**注意：** 未配置 `DEEPSEEK_API_KEY` 时返回 `500`，需在 `.env` 中填写。

### SSE 事件协议

每条 SSE 消息格式：`event: <事件名>\ndata: <JSON>\n\n`

| 事件名 | 触发时机 | data 结构 |
|---|---|---|
| `start` | 开始生成 | `{"type":"start","messageId":"..."}` |
| `delta` | 每生成一段文字 | `{"type":"delta","delta":"增量文本","content":"累计完整文本"}` |
| `done` | 生成完成 | `{"type":"done","message":{...助手消息完整对象...}}` |
| `error` | 处理出错 | `{"type":"error","messageId":"...","error":"错误信息"}` |

**完整事件流示例：**

```
event: start
data: {"type":"start","messageId":"448d7e72..."}

event: delta
data: {"type":"delta","delta":"前端","content":"前端"}

event: delta
data: {"type":"delta","delta":"转AI","content":"前端转AI"}

event: done
data: {"type":"done","message":{"messageId":"e88c8abe...","role":"assistant","content":"前端转AI…","status":"succeeded","actions":[],"agentTrace":{"status":"succeeded","activeStepId":null}}}
```

**前端消费伪代码：**

```js
const es = new EventSource(url)
es.addEventListener('delta', (e) => {
  const data = JSON.parse(e.data)
  console.log(data.delta)   // 增量文本
})
es.addEventListener('done', (e) => {
  es.close()                // 完成后关闭连接
})
es.addEventListener('error', (e) => {
  console.error(e)
})
```

## 7. 岗位大类推荐

### `POST /jobs/recommend`

根据用户画像 + 求职意愿做向量检索，推荐适合的**岗位大类**（无 LLM 参与）。供 Java `career-service` Feign 直连（服务间调用），前端主流程不直接调用。

**请求体：** 普通 JSON 对象即可。Python 会对请求体**整段文本**做向量嵌入后再余弦检索，因此建议把画像与求职意愿都放进去；也兼容 Feign 的「JSON 字符串字面量」双编码格式（`decode_query_text` 自动解码一层后按内层文本嵌入）。

```json
{
  "userId": "111",
  "求职意愿": {
    "preferredJobKeywords": ["前端开发"],
    "cityIntents": ["杭州", "西安"]
  },
  "profile": { "姓名": "张三", "技能": ["Java", "Spring Boot"] }
}
```

**处理流程：**
1. 对请求体文本嵌入（DashScope `text-embedding-v1`，1536 维）
2. 在 `job_category_vector` 表余弦检索：`topK=5`、相似度阈值 `0.3`
3. 返回每条结果的 `metadata.nodeName` 组成的数组

**响应 `200`（`text/plain`，裸 JSON 数组）：**

```json
["Java_国际化或特定领域技术工程师", "Python_数据分析工程师"]
```

无匹配结果或内部异常时返回空数组：

```json
[]
```

## 8. 具体岗位推荐（向量检索 + DeepSeek 精排）

### `POST /jobs/recommend/specific`

根据用户画像 + 求职意愿做向量检索，再由 DeepSeek 精排出 1 个最佳匹配 + 最多 4 个其他推荐岗位，返回 **MatchJob 结构**。**前端「推荐岗位」功能直连此接口**（`aiHttp`，不经过 Java 网关）。

**请求体：** 同第 7 节，普通 JSON 对象（整段文本用于嵌入和 LLM 提示），建议包含 `求职意愿` + `profile`：

```json
{
  "userId": "111",
  "求职意愿": {
    "preferredJobKeywords": ["前端开发"],
    "cityIntents": ["杭州", "西安"],
    "salaryRange": "8k-16k",
    "benefits": ["双休", "五险一金"]
  },
  "profile": { "技能": ["Vue", "TypeScript"], "工作年限": "3年" }
}
```

**处理流程：**
1. 嵌入请求体 → 在 `job_detail_vector` 表余弦检索：`topK=5`、相似度阈值 `0.2`
2. 从每条结果的 metadata 提取候选岗位（`jobId / jobName / companyName / city / district / level / educationRequirement / salaryNormalized / salaryMin / salaryMax / updatedAtRaw`，缺字段为 `null`）
3. DeepSeek（`deepseek-v4-flash`，关闭思考模式）按系统提示的 JSON Schema 精排，输出 1 个 `bestMatch` + 最多 4 个 `otherRecommendations`

**响应 `200`（`text/plain`，裸 JSON）：**

```json
{
  "bestMatch": {
    "jobId": "JOB20240801001",
    "jobName": "Java 开发工程师",
    "companyName": "某科技公司",
    "city": "杭州",
    "educationRequirement": "本科",
    "salaryNegotiable": true,
    "salaryNormalized": "15K-25K",
    "updatedAtRaw": "",
    "level": "P6",
    "overallScore": 90,
    "matchTags": ["高匹配", "技术栈重合"],
    "dimensionScores": {
      "basicRequirement": 85,
      "professionalSkill": 92,
      "professionalLiteracy": 88,
      "developmentPotential": 90
    }
  },
  "otherRecommendations": [
    {
      "jobId": "JOB20240801002",
      "jobName": "Python 后端工程师",
      "companyName": "某数据公司",
      "city": "西安",
      "educationRequirement": "本科",
      "salaryNegotiable": false,
      "salaryNormalized": "12K-20K",
      "updatedAtRaw": "",
      "level": "P5",
      "overallScore": 82,
      "matchTags": ["技能相关", "薪资略低但发展好"]
    }
  ]
}
```

> 字段说明：`dimensionScores` 仅 `bestMatch` 有，`otherRecommendations` 无；`salaryNormalized` / `updatedAtRaw` 由 LLM 推断，`updatedAtRaw` 常为空字符串。

**错误响应**（HTTP 200，body 为 `text/plain` 的 error JSON，前端据 `error` 字段提示）：

```json
{ "error": "未找到匹配的岗位信息" }
```

| error 内容 | 场景 |
|---|---|
| `向量库不可用` | pgvector 连接池初始化失败（服务仍可启动，只是无检索能力） |
| `未找到匹配的岗位信息` | 向量检索无结果（相似度都低于阈值 0.2） |
| `模型返回解析失败` | DeepSeek 返回内容不是合法 JSON |
| `模型返回格式不正确` | JSON 中缺 `bestMatch` 字段 |
| `系统内部错误: <异常>` | 其它运行时异常 |

## 附：完整调用时序（一次对话）

```
1. POST /sessions/{sessionId}           → 创建会话，拿到 sessionId
2. POST /sessions/{sessionId}/messages  → 存用户消息，拿到 assistantMessage.messageId + stream.url
3. GET  stream.url (SSE)                → 收 start/delta/done，AI 回复逐字展示
4. GET  /sessions/{sessionId}/messages  → 下次打开会话时展示历史
```

## 常见错误

| HTTP 状态码 | code | 场景 |
|---|---|---|
| `404` | 404 | 会话不存在 / 消息不存在 |
| `422` | 422 | 请求参数校验失败（如 `content` 为空） |
| `500` | 500 | 未配置 `DEEPSEEK_API_KEY` 或 AI 调用出错 |
